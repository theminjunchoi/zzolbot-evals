# 25. 학습 효과가 모델 크기를 바꿔도 재현되는가

> **사전 등록 절(1~5)은 결과를 보기 전에 쓰고 커밋했다.** 결과 절은 측정 후 채운다.

## 1. 왜 이 질문인가

리포트 12번의 데이터 비율 곡선은 **1.5B 한 점에서만 그렸다.** "학습 데이터의 정답
비율이 모델의 판단 성향을 좌우한다"가 이 레포의 대표 결론인데, 그것이 이 크기에서만
성립하는 이야기인지 크기와 무관한 이야기인지 모른다. 지금 문서들은 후자인 것처럼
읽힌다.

## 2. 원래 설계를 기각한 기록

처음 세운 설계는 **크기 3종 x 비율 3종 = 9회 학습**으로 곡선을 세 번 긋는 것이었다.
리포트 24번에서 **계산으로 기각했다.**

- n=33에서 짝지은 보상 차이의 MDE는 **0.115**
- 비율 곡선의 전체 폭은 **0.0788로 이미 한계 아래**
- 곡선 모양 변화를 상호작용으로 잡으려면 **약 337종** 필요

9회를 돌렸다면 무엇이 나오든 노이즈와 구별할 수 없었다.

## 3. 답할 수 있게 바꾼 질문

**"학습 데이터 비율의 효과가 모델 크기를 바꿔도 재현되는가."**

크기마다 **학습 전과 학습 후 두 팔만** 잰다. 1.5B에서 그 차이가 **+0.218**이었고
MDE 0.115의 두 배에 가까워 검출된다.

| 크기 | 학습 전 | 학습 후 | 필요 작업 |
|---|---|---|---|
| 0.5B | ? | ? | 학습 1회 + 평가 2회 |
| **1.5B** | **0.570** | **0.906** | **없음** (기존 측정 재사용) |
| 3B | ? | ? | 학습 1회 + 평가 2회 |

4bit를 쓰는 이유는 1.5B의 두 팔이 이미 4bit로 측정돼 있어서다. bf16으로 가면 1.5B를
다시 학습해야 하고 기존 곡선과의 비교도 끊긴다.

## 4. 고정한 것과 바꾼 것

**바꾸는 축은 모델 크기 하나다.**

| 항목 | 값 | 비고 |
|---|---|---|
| 데이터 | `training/data/sft-v6` (166 train / 22 valid) | 동일 |
| 스텝 | 781 | 노출 횟수를 맞춘다 |
| batch / max_seq_length | 1 / 3200 | 동일. 최장 샘플이 3086 |
| 학습률 | 1e-4 | **고정. 아래 교란 참조** |
| 옵티마이저 | adam | mlx-lm 기본 |
| LoRA rank / scale | 8 / 20.0 | 동일 |
| **LoRA 레이어** | **전체의 57%** | 0.5B 14/24, 1.5B 16/28, 3B 21/36 |

**레이어를 개수(16)가 아니라 비율(57%)로 맞춘 이유**: 개수를 고정하면 0.5B는 24개 중
16개가 걸려 전체의 67%가 되고, 3B는 36개 중 16개로 44%가 된다. **작은 모델일수록
상대적으로 더 많이 학습시키는 교란**이 생긴다.

### 명시하는 교란: 학습률

**크기마다 최적 학습률이 다를 수 있다.** 1e-4를 고정하면 "크기만 바꿨다"가 되지만,
어느 크기에서 효과가 안 나왔을 때 **"크기 때문"인지 "그 크기에 1e-4가 안 맞아서"인지
가를 수 없다.**

공짜로 막는다. **모든 실행의 train/val loss를 남긴다.** 효과가 없는데 loss가 정상적으로
떨어졌다면 학습은 됐고 능력 문제다. loss가 안 떨어졌다면 학습률을 의심한다. 결과를 본
뒤에는 되돌릴 수 없으므로 지금 정한다.

## 5. 사전 등록한 판정 기준과 예측

**주 종점**: 크기별 (학습 후 - 학습 전) 보상 차이. 알림 단위 군집 부트스트랩,
`analysis/power_cli`로 계산한다.

| 판정 | 조건 |
|---|---|
| **재현** | 그 크기에서 차이가 MDE(약 0.115)를 넘고 부호가 양수 |
| **미재현** | 차이가 MDE 아래이거나 음수 |
| **판정 보류** | 파싱 실패가 33종 중 5종을 넘으면 종점이 형식 실패에 오염된 것으로 본다 |

**중단 규칙**: 3B 학습에서 val loss가 발산하면 그 자리에서 멈추고 학습률을 기록한다.
결과에 맞춰 학습률을 바꾸지 않는다.

### 결과 보기 전 예측

1. **3B: 재현되나 효과가 작아진다.** 베이스가 이미 높아 헤드룸이 좁다. 1.5B의 +0.218보다
   작을 것이고, **MDE 0.115를 못 넘을 수도 있다.** 그러면 "미재현"으로 기록하되
   헤드룸 축소와 구별되지 않음을 명시한다
2. **0.5B: 갈린다.** 형식을 못 지켜 파싱 실패가 많으면 학습이 형식부터 가르쳐 효과가
   1.5B보다 **클 수도** 있고, 판별 자체를 못 배워 효과가 없을 수도 있다
3. 셋 중 하나라도 미재현이면 **README의 "데이터 비율이 판단 성향을 좌우한다"에 크기
   조건을 달아야 한다**

**0.5B에서 효과가 안 나오면 그쪽이 더 흥미롭다.** "이 방법은 일정 크기 이상에서만
작동한다"가 되고, 그건 큰 효과라 지금 표본으로도 말할 수 있다.

## 6. 실측한 소요 시간

추측하지 않고 20스텝씩 재서 외삽했다.

| 모델 | 레이어 -> LoRA | s/step | 781스텝 | 피크 메모리 |
|---|---|---|---|---|
| Qwen2.5-0.5B-4bit | 24 -> 14 | 2.03 | 26분 | 12.9GB |
| Qwen2.5-1.5B-4bit | 28 -> 16 | 3.84 | 50분 | (기존) |
| Qwen2.5-3B-4bit | 36 -> 21 | 6.22 | 81분 | 24.7GB |

**시간이 파라미터 수에 비례하지 않는다.** 0.5->1.5B(3배)에 1.89배, 1.5->3B(2배)에
1.62배로 대략 `시간 ∝ 파라미터^0.55`다. 시퀀스 3200에서 어텐션과 활성값 비용이
파라미터에 비례하지 않기 때문이다. 학습 2회와 평가 4회로 **약 2시간**이다.

**0.5B인데 피크가 12.9GB인 것에 주의한다.** 4bit 가중치는 0.3GB뿐이고 나머지가 전부
활성값이다. 리포트 21번에서 torch가 1.5B에 28.9GB를 쓴 것과 같은 구조다.
