# DPO, 그리고 RL이 언제 도움이 되는가

D단계(DPO)를 실행하고, 앞선 RFT 실패를 해석하기 위해 **대조군**을 돌린 기록이다.

두 가지를 말할 수 있게 됐다.

1. **헤드룸이 RL의 부호를 바꾼다.** 다만 유리한 쪽에서도 개선이라 부를 크기가 아니다
2. **경고를 사람이 읽고 판단하는 구조는 실패한다.** 실제로 무시했고, 코드로 막으니 막혔다

## 1. DPO: 두 번 돌렸고 둘 다 사전 등록 기준 미달

| 팔 | beta | 보상 | 인용 | 오탐 |
|---|---|---|---|---|
| v6 (DPO 없음) | - | **0.906** | 9/15 | **1/18** |
| v6 + DPO | 0.1 | 0.761 | 9/15 | 11/18 |
| v6 + DPO | 0.5 | 0.864 | 10/15 | 5/18 |
| v6 + 제약 | - | **0.955** | 13/15 | **1/18** |
| v6 + DPO + 제약 | 0.1 | 0.833 | **15/15** | 11/18 |
| v6 + DPO + 제약 | 0.5 | 0.924 | **15/15** | 5/18 |

오탐은 **접지 전 원 주장 기준**이다(모델의 판별력). 다른 리포트와 같은 정의를 쓴다.
`reward_cli`가 보고하는 오탐 열은 접지 후 값이라 이보다 낮게 나온다.

사전 등록 기준은 "오탐 2/18 이하 AND 인용 유지"였다. **둘 다 미달이다.**

### 인용 15/15는 주목할 값이다

**로컬 팔이 인용 100%를 찍은 것은 처음이고 Gemini와 같다.** 두 beta에서 모두 재현됐다.
DPO가 "근거를 주장하라"를 확실히 가르쳤고 제약 디코딩이 인용을 정확하게 만든다.

**오탐만 잡으면 매우 강한 팔이다.** 그리고 오탐은 선호 쌍의 편중에서 온다.

### 편중은 필터 문제가 아니라 구조적 사실이다

첫 실행의 선호 쌍이 **예 15 / 아니오 2, 88% 양성**이었다. 마진 기준을 낮추면 균형이
맞을 줄 알고 재봤다.

| 마진 기준 | 예 | 아니오 | 예 비율 |
|---|---|---|---|
| 0.5 | 12 | 4 | 75% |
| 0.2 | 17 | 4 | 81% |
| **0.001** | **17** | **4** | **81%** |

**기준을 0.001까지 낮춰도 음성 쌍은 4개가 최대다.**

이유는 단순하다. **음성 16종 중 12종은 8번 다 정답이다.** v6가 음성에서 이미 잘하니
(오탐 1/18) 대비시킬 나쁜 샘플이 존재하지 않는다. **rejected가 없으면 쌍이 없다.**

### 두 번째 원인: 길이 편향 (2026-08-29 추가 확인)

구현을 검증하다 찾았다. **DPO 손실은 로그 확률의 합을 쓰는데, 우리 쌍은 chosen이 훨씬 길다.**

```
chosen  (교사 출력):  평균 360 토큰,  범위 250~480
rejected(모델 최저):  평균 273 토큰,  범위 184~410
chosen이 더 긴 쌍: 14/17 (82%)
```

길수록 로그 확률 합이 작아지므로, 모델이 마진을 키우는 가장 쉬운 길이
**"길게 쓰면 좋은 것"**을 배우는 것이다. DPO의 알려진 length bias이고,
우리 데이터는 82%가 그 방향이다.

**판정 편중(88% 양성)과 길이 편향(82%)이 같은 방향으로 작용했다.**
"길고 자세하게 근거를 설명하는" 출력을 선호하게 되면 근거를 더 자주 주장한다.
오탐 1/18 → 5/18이 그 결과다.

처방은 **길이 정규화**다. 합 대신 토큰당 평균을 쓴다(SimPO 등이 쓰는 방식).

```python
return picked.sum()     # 지금
return picked.mean()    # 길이 정규화
```

> **이 처방은 [리포트 19번](19-판정확률과-캘리브레이션.md)에서 철회했다.** DPO 팔의
> AUC가 0.874로 SFT 기준선(0.933)보다 낮아, 편향을 고쳐도 동작점이 옮겨질 뿐
> 곡선이 올라간다는 근거가 없다.

### 구현 자체는 정확하다

같은 검증에서 확인한 것이다.

| 검사 | 결과 |
|---|---|
| 손실 수식 (가짜 모델 11개 테스트) | 통과 |
| **학습 전 손실 = log 2** | **정확히 0.693147** |
| 학습 전 암묵 정확도 = False | 맞음 |
| 프롬프트 마스킹 | 맞음 (안 그러면 log 2가 안 나온다) |
| LoRA만 학습 | 224 텐서, 전부 lora |
| 어댑터가 실제로 갱신됨 | 224/224 변경 |

**"테스트가 통과하니 구현이 맞다"에서 멈추면 안 된다.** 가짜 모델 테스트는 수식이
수식대로 계산되는지만 본다. 실제 모델에서 참조가 제대로 잡히는지(log 2 검사)와
데이터가 손실을 왜곡하지 않는지(길이 편향)는 별개다.

### beta가 예상대로 작동했다

```
beta 0.1   step 20 손실 0.0000,  에폭 2 평균 0.0001   ← 붕괴
beta 0.5   step 10 손실 0.16975, 에폭 1 평균 0.09987  ← 정상
```

beta는 정책이 참조에서 얼마나 멀어질 수 있는지를 억제한다. 0.1은 17개 쌍에 완전히
과적합해 판정 성향이 통째로 밀렸다. 0.5로 올리니 오탐이 10/18에서 4/18로 절반 회복됐다.

## 2. 경고를 만들어놓고 무시했다

첫 DPO 실행의 로그다.

```
선호 쌍 17개
  채택: 예 15 / 아니오 2
  제외된 것의 판정 분포: {'아니오': 12, '예': 7}  ← 한쪽에 몰리면 비율이 밀린다
```

**저 화살표 문구는 30분 전에 RFT 실패를 보고 직접 넣은 것이다.** 주석에 "같은 일을
다시 겪지 않으려면 세어야 한다"고까지 썼다.

**그리고 88% 편중을 보고도 학습을 돌렸다.** 손실이 20스텝 만에 0이 된 것도 지나쳤다.

**계측을 만들어놓고 안 읽는 것은 계측이 없는 것보다 나쁘다.** 있다고 믿기 때문이다.

### 그래서 코드가 막게 했다

```python
# 가드 1: 판정 편중
if skew > args.max_skew and not args.allow_skew:
    print("중단: 편차가 15%를 넘는다. 학습하면 판정 성향이 그쪽으로 밀린다.")
    print("      그래도 돌리려면 --allow-skew. 그 경우 beta를 올려 참조에서 "
          "멀어지지 않게 하라.")
    return 2

# 가드 2: 손실 붕괴
if recent < args.collapse_at:
    print("조기 종료: 쌍 N개에 과적합한 것이다.")
```

**실제로 막았다.** 편차 28%로 학습이 시작되지 않았고, 메시지가 알려준 대로 beta를
올려 다시 돌리니 오탐이 절반으로 줄었다.

**같은 정보를 로그로 찍었을 때는 무시했고, 종료 코드로 막으니 따랐다.**

## 3. 대조군: 부호는 뒤집혔으나 개선이라 부를 크기가 아니다

RFT와 DPO가 둘 다 실패한 뒤, 두 가지 해석이 가능했다.

1. 이 태스크에서 RL이 원래 안 된다
2. **헤드룸이 없을 때 RL이 안 된다**

**구별하려면 대조군이 필요하다.** v4를 출발점으로 **완전히 같은 절차**를 돌렸다.
같은 프롬프트 40종, 같은 보상, 같은 코드, 같은 하이퍼파라미터. 출발 모델만 다르다.

### 결과 보기 전에 적은 예측

| 항목 | 예측 | 실제 | |
|---|---|---|---|
| v4 그리디 (신규 40종) | 0.80~0.86 | **0.835** | 적중 |
| BoN 여유 | +0.10 이상 | **+0.135** | 적중 |
| 만점 8/8 프롬프트 | 10종 이하 | 11종 | 빗나감 |
| **RFT 후 보상** | **상승** | **+0.027** | **적중** |

### 부호가 뒤집혔다

| 출발 팔 | 헤드룸 | RFT 전 | RFT 후 | 변화 | RFT 후 오탐 |
|---|---|---|---|---|---|
| v6 | +0.035 | 0.906 | 0.876 | **-0.030** | 1 → 0/18 |
| **v4** | **+0.135 (3.9배)** | 0.788 | 0.815 | **+0.027** | 7 → 8/18 |

**같은 코드가 한쪽에서는 도움이 되고 다른 쪽에서는 손해다.** 차이는 출발 모델의
헤드룸뿐이다.

### 시나리오 단위로 보면 개선이 아니다

보상 +0.027을 시나리오별로 뜯으면 이렇다.

```
v4 → v4+RFT:  개선 6종 / 악화 5종   부호검정 p = 1.00
```

**순증가가 1종이다.** 그리고 개선 6종 중 하나는 파싱 실패가 고쳐진 것(0.00 → 1.00)이라
형식 점수 회복이지 판단 개선이 아니다.

항목별로도 개선이 없다.

| | 보상 | 인용 | 오탐 |
|---|---|---|---|
| v4 → v4+RFT | +0.027 | **+0** | **+1 (악화)** |
| v6 → v6+RFT | -0.030 | -2 | -1 |

**"헤드룸이 있으면 RL이 도움이 된다"는 이 데이터로 말할 수 없다.**
말할 수 있는 것은 **부호가 뒤집힌다**까지이고, 유리한 쪽조차 노이즈와 구별되지 않는다.

### 다만 v4에서도 오탐은 나빠졌다

보상은 올랐지만 **오탐이 7/18에서 8/18로 늘었다.** 인용은 10/15로 유지됐다.
즉 v4에서 얻은 +0.027은 **인용이나 판정이 아니라 형식과 부분 점수에서 온 것**이고,
판정 성향은 v6 때와 마찬가지로 "예" 쪽으로 밀렸다.

**"헤드룸이 있으면 RL이 도움이 된다"는 결론은 총점 기준에서만 성립한다.**
판정 축만 보면 두 팔 모두 나빠졌다. 이것도 정직하게 적어야 한다.

RFT 학습 데이터의 예 비율이 57%로 원래 풀(60%)보다 낮았는데도 오탐이 늘었다는 점은
비율만으로 설명되지 않는다. **자기증류(27건, 73%)가 v4의 기존 오탐 성향을 굳혔을
가능성이 있으나 분리해서 확인하지 않았다.**

두 번째 요인도 함께 드러났다.

| | RFT의 실제 기여 | 학습 데이터 예 비율 (원래 풀 60%) |
|---|---|---|
| v6 | 4건 | 56% (제외가 전부 "예" 쪽) |
| **v4** | **10건 (2.5배)** | **57%** (제외 3건이 고르게 분포) |

v4 쪽이 기여도 크고 비율 왜곡도 덜하다. **두 요인이 같은 방향으로 작동했다.**

## 4. 그래도 RL이 SFT를 못 이긴다

정직하게 적어야 할 결론이다.

```
v4 + RFT     0.815
v6 (SFT만)   0.906
v6 + 제약    0.955   ← 최고
```

**RL이 도움이 되는 구간이 있다는 것은 보였지만, 그 구간에서 얻는 것보다
SFT로 얻는 것이 크다.** 이 태스크에서는 그렇다.

## 5. 왜 이 태스크에서 RL이 약한가

세 지렛대가 모두 막혀 있다. **그리고 셋 다 v6가 이미 좋아서 생긴 결과다.**

| 필요 조건 | 현재 |
|---|---|
| 헤드룸 | +0.035 (v4의 4분의 1) |
| 보상이 실패를 봄 | 6종 중 2종 |
| 균형 잡힌 선호 쌍 | 음성 16종 중 12종이 8번 다 정답 |

**RL을 곡선의 잘못된 지점에 적용했다.** SFT 세 번과 제약 디코딩으로 격차를 먼저
다 좁혀놓고, 남은 부스러기에 RL을 걸었다. 순서가 틀렸다.

### 한 가지 자기 비판

"학습 데이터의 판정 비율이 방법론보다 지배적이다"를 세 번 재현된 발견이라고 썼는데,
**일부는 배점 설계가 만든 것이다.** 보상의 절반(0.5)이 판정이니 판정을 미는 개입이
점수를 지배하는 것은 어느 정도 당연하다.

데이터 비율이 모델의 판정 성향을 좌우한다는 것은 실측이다. 다만 "방법론보다 지배적"이라는
표현은 이 배점 위에서만 성립한다.

## 6. 말할 수 있는 것과 없는 것

**말할 수 있다**
- DPO를 맨바닥에서 구현해(mlx-lm에 없다) 가짜 모델로 수식을 검증하고 실제로 돌렸다
- **헤드룸이 RL의 부호를 바꾼다.** 같은 코드로 출발 모델만 바꾸니 +0.027과 -0.030으로 갈렸다
- beta가 붕괴를 막는다. 0.1에서 손실이 0으로 무너지고 0.5에서 정상 범위였다
- 선호 쌍의 편중은 필터 문제가 아니라 **모델이 이미 잘하면 rejected가 없다**는 구조적 사실이다

**말할 수 없다**
- DPO의 실패가 편중 때문만이다 — **길이 편향(82%)이 같은 방향으로 겹쳤다.**
  둘을 분리하지 않았다
- **헤드룸이 있으면 RL이 도움이 된다** — v4에서도 개선 6 / 악화 5로 p = 1.00이고
  인용은 그대로, 오탐은 오히려 늘었다. 부호가 뒤집힌다는 것까지만 말할 수 있다
- 이 결론이 시드에 재현된다 — **각 팔을 시드 하나로만 돌렸다.** 차이가 0.027과 0.030이라
  시드 노이즈와 구별되지 않을 수 있다
- DPO가 원리적으로 안 된다 — 균형 잡힌 쌍으로는 시도하지 못했다(쌍이 존재하지 않아서)
- 인용 15/15가 유지되는 설정을 찾았다 — 그 팔은 오탐이 5/18로 나쁘다
