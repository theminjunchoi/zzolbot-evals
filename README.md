# zzolbot-evals

운영 모니터링 봇 [zzolbot](https://zzol.site)의 LLM 알림 분석 품질을 평가하고 개선하는 프로젝트다. 실제 프로덕션 오진 사례에서 출발해, 골든 시나리오 기반 평가셋을 만들고, 오답 유형을 분석하고, 개선을 측정하는 학습 개선 사이클을 목표로 한다.

## 배경

zzolbot은 Alertmanager 웹훅으로 알림을 받아 Loki 로그를 근거로 LLM(gemini-2.5-flash)이 근본 원인을 분석해 Slack에 게시하는 봇이다. 2026-07 실제 운영에서 "IP 차단 급증 알림에 무관한 카드게임 에러 로그를 원인으로 지목"하는 오진이 13건 반복됐고, 이 프로젝트는 그 재발 방지와 품질 측정에서 시작했다.

## 구조

```
golden-set/monitor/   monitor 경로 골든 시나리오 20종 + 설계 문서
reports/              측정 리포트와 원본 응답 JSON
```

## 현재 상태 (2026-08-26)

- 골든 시나리오 확정 20종: 근거 있음 10, 근거 없음 10, 알림 종류 15개, 대조군 쌍 4개
- 모든 시나리오는 실제 시스템 값(로그 포맷, 로거 축약, 스레드명, 알림 룰 템플릿, 인프라 설정)과 정합하도록 코드 실측으로 검증했다
- 자바 하네스 baseline: **18/20 PASS**. FAIL 2건은 시간적 접지(재적재 타임스탬프)와 양적 접지(희소 로그) 축으로, 대조군 실험으로 체계적 약점임을 입증

## 로드맵

1. 프롬프트에 시간/양 정합성 규칙 추가 후 전후 비교 (진행 예정)
2. Python 평가 하네스 재구축과 공식 baseline (반복 실행, 분산 포함)
3. 시나리오 100~200종 합성 확장 + rule 필터/LLM judge 품질 검증 자동화
4. 소형 오픈모델 SFT 및 학습 전후 성능 비교
5. 인용 검증을 verifiable reward로 쓰는 RLVR(GRPO) 실험
